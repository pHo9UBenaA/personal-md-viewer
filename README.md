# Markdown Viewer

ローカルの Markdown を、パス入力・フォルダー選択・タブで読むための読み取り専用ツールです。Node.js 24 以上と pnpm 10.33.2 を使います。ビルドは不要です。

## 起動

開発時は Caddy を導入したうえで `pnpm dev` だけで起動できます。

```sh
pnpm dev
# 必要なら、起動時に開くパスも指定できます
pnpm dev "/Users/you/Documents/notes"
```

URL は `http://md.localhost:8080` です。sudo 不要で Caddy と閲覧サーバーを起動し、Ctrl+C で両方を終了します。`src` / `public` の変更で閲覧サーバーを再起動するので、ブラウザーを再読み込みしてください。既存の Caddy 設定や常駐サービスは変更しません。

8080 番と内部の 3100 番が必要です。使用中なら `DEV_PORT=8081 DEV_BACKEND_PORT=3101 pnpm dev` のように変更できます。`PORT` / `VIEWER_ORIGIN` は dev では自動設定します。

ポート番号なしの HTTP URL に必要な 80 番待受は、環境によって追加権限が必要です。Caddy が 80 番で待ち受けられる環境では `DEV_PORT=80 pnpm dev` も使えます。スクリプト自体は sudo を実行せず、番号なしの設定に自動変更もしません。

開発時以外に閲覧サーバー単体を起動する場合は以下を使います。

```sh
pnpm install --frozen-lockfile
pnpm start

# 起動時にファイルやフォルダーを開く（空白を含むパスは引用符で囲む）
pnpm start "/Users/you/Documents/notes"
pnpm start "/Users/you/Documents/one.md" "/Users/you/Documents/two.md"
pnpm start --recursive "/Users/you/Documents/notes"

# 3000 番ポートが使用中の場合
PORT=0 pnpm start
```

表示された `http://127.0.0.1:...` をブラウザーで開いてください。起動時のブラウザー自動操作はありません。終了はターミナルで Ctrl+C。サーバーは `127.0.0.1` のみに接続を受け付けます。

## 読み方

### ポート番号を使わないローカル URL

付属の [Caddyfile](Caddyfile) は `http://md.localhost` を `127.0.0.1:3000` に転送します。Caddy は別途インストールが必要な任意の構成です。

```sh
# 閲覧サーバー（通常のユーザー権限で起動）
VIEWER_ORIGIN=http://md.localhost pnpm start

# 別のターミナル: Caddy が導入済みで80番の待受権限を持つ場合
caddy run --config ./Caddyfile
```

Caddy はループバックだけで待ち受け、証明書の発行や OS の信頼ストア変更はしません。80 番が使用中なら既存の Caddy 設定にサイトブロックを統合してください。80 番への bind が拒否される環境では、Caddy 側のサービス権限を設定する必要があります。閲覧サーバーは通常ユーザーのまま使ってください。

`.localhost` をループバック解決するブラウザー向けの名前です。環境が解決しない場合はローカル DNS / hosts の設定が必要です。別の名前に変更する場合は Caddy のサイト名と `VIEWER_ORIGIN` を同じオリジンに揃えてください。`VIEWER_ORIGIN` は完全一致で検査し、任意の Host や転送ヘッダーを信用しません。設定中は通常の `127.0.0.1:3000` の Host は拒否します。

### ファイル操作

| 操作 | 動作 |
| --- | --- |
| パスを入力して「開く」 | ファイルは 1 タブ、フォルダーは直下の `.md` / `.markdown` を全件アプリ内タブで開く |
| 「サブフォルダーも含める」 | パスからフォルダーを開くときに再帰的に探す |
| ファイル・フォルダーを選択 | ブラウザーが渡すファイル内容を読む。フォルダー選択は配下の Markdown 全件が対象 |
| ドラッグ＆ドロップ | ファイルやフォルダーを開く。フォルダーは対応ブラウザーで再帰的に読む |
| ⌘⇧P / Ctrl+Shift+P | パスを入力して開く、または取り込み済みのファイル名を検索。↑↓ と Enter でも選べる |
| ⌘⇧F / Ctrl+Shift+F | 閲覧中のタブを画面全体に表示、または通常表示に戻す。Esc でも戻せる |
| ファイルツリー上で ⌘← | 展開されているフォルダーをすべて閉じる |
| タブの ← → / Home / End | 選択タブを切り替える。Delete で選択タブを閉じる |
| ブラウザーの戻る・進む | タブの選択と開閉を履歴から復元する。再読み込み後はパスで開いたファイルを開き直す |
| 目次・Markdown 内の相対リンク | 見出しへ移動、またはリンク先の Markdown をアプリ内タブで開く |
| 再読み込み | パスで開いたファイルをディスクから読み直す |
| ソース | Markdown 原文とプレビューを切り替える |
| 別タブで開く | パスで開いたファイルを別のブラウザータブで読む。同じサーバー起動中のみ有効 |
| ライトへ / ダークへ | 画面と本文のテーマを切り替える。初回は OS 設定、以後は選択したテーマを使用 |

絶対パス、`~/...`、起動したディレクトリからの相対パスに対応します。パスで開いた同じ実ファイルはアプリ内で重複しません。ブラウザーのファイル選択からは絶対パスを取得できないため、ファイル内容を読み込む方式に分けています。

ブラウザーの大量ポップアップを避け、フォルダーの一括表示はアプリ内タブにしています。パスで開いたタブのパスと参照元フォルダーはブラウザーのセッション履歴に保存し、同じタブの再読み込み後も復元します。ファイル内容は保存せず、復元時にディスクから読み直します。ブラウザーで選択・ドロップしたファイルは選択時点の内容です。再読み込み後は再度取り込んでください。ブラウザーのセッション履歴を消去した場合も復元できません。起動引数で指定したファイルは、新しい履歴では再び開かれます。

## 対応範囲と制限

テーマのみ localStorage に保存します。同じホスト・ポートの別タブにも反映されます。保存が禁止された環境でも、そのページ内での切り替えは利用できます。

- 見出し、リスト、表、取り消し線、引用、コード、リンクに対応します。GFM 完全互換ではありません。タスクリスト・脚注の専用拡張はありません。
- 生 HTML はテキストとして表示します。Mermaid はコード表示です。HTML の `<details>`、SVG、数式、構文色分けは描画しません。
- 外部画像を自動取得しません。ローカル画像は PNG / JPEG / GIF / WebP / AVIF に対応。HTML や SVG を画像として配信しません。
- ファイルをパスで開いた場合、相対参照の許可範囲は親フォルダーです。フォルダーから開いた場合は選択したフォルダー以下です。範囲外の Markdown はパス入力で明示的に開いてください。
- ブラウザー選択で相対画像も読みたい場合は、画像を含むフォルダーを選択してください。相対 Markdown リンクは同じ選択で開いたタブを対象にします。
- ファイル件数、タブ数、登録総数、探索項目数の固定上限はありません。本文は選択時に読み込みます。非常に多い場合の探索時間やタブ一覧のメモリー使用量はファイル数に応じて増えます。
- Markdown は 1 ファイル 1 MiB、画像は 1 ファイル 5 MiB。フォルダー探索は深さ 32 まで。これらの保護は継続しています。
- パスの再帰探索では `.git` / `node_modules` とシンボリックリンクをスキップします。ブラウザー選択の合計サイズは 50 MiB までです。
- 本文のキャッシュは直近 10 タブ。キャッシュから外れたタブも再び選択すれば読めます。

## 安全性

ファイルを書き換える API やシンボリックリンクを作成する機能はありません。Host / Origin / Fetch Metadata の検査と起動ごとのランダムトークンで、別サイトからのファイル操作を拒否します。実パスによる参照範囲の検査、通常ファイルの確認、サイズ制限、固定した静的ファイルの配信を行います。

Markdown は `html: false` で処理し、リンク・画像 URL はいったん無効な属性に移します。本文 iframe は専用 CSP でスクリプト・フォーム・外部リソースを禁止します。WebKit で親ページが登録したイベントを使うため sandbox に `allow-scripts` と `allow-same-origin` を含めていますが、本文 CSP の `script-src 'none'` は維持します。この CSP を緩めないでください。

ローカルの本人利用向けです。同じ OS ユーザー権限で動く悪意あるプロセス、ブラウザー拡張、OS 自体の侵害を防ぐ仕組みではありません。リバースプロキシもローカル限定で使ってください。外部公開は対象外です。脆弱性やバグが一切ないことを保証するものではありません。

## 開発・検証

```sh
pnpm dev
pnpm check
pnpm test
pnpm exec playwright install chromium webkit
pnpm test:e2e
pnpm audit
```

テストは一時ディレクトリの実ファイルを使います。ブラウザーテストは Chromium と WebKit で選択、タブ、コマンドパレット、リンク、画像、CSP、モバイル幅を検証します。旧 `/view`・`/files`・`/sources` ルートと Mermaid ビルドは廃止しました。

## 構成と依存の方針

実行時の直接依存は markdown-it のみです。サーバーは Node.js 標準 HTTP、画面はブラウザー標準 API で実装し、ビルドを不要にしています。単一画面のローカル閲覧に用途を絞っているため、現在は Hono / HonoX や UI フレームワークを採用していません。依存を減らす代わりに、HTTP のアクセス制御や DOM 操作はこのプロジェクトで保守します。

markdown-it は、生 HTML を無効にする `html: false` を標準オプションで指定できるため採用しています。Marked より一般的に高速・安全という判断ではありません。Markdown パーサーは自作せず、追加プラグインも使いません。本文はタブを選択したときに読み込み、描画済みの本文を保持する件数を抑えています。

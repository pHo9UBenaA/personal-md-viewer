# 開発ガイド

必要環境、開発サーバー、ローカルプロキシ、検証手順を扱う。コマンドはリポジトリ直下で実行する。閲覧サーバーとプロキシはローカルの本人利用に限定し、外部公開しない。閲覧サーバーは通常ユーザーで起動する。

## 準備

通常の閲覧・開発ともに、Node.js 24 以上と pnpm 10.33.2 が必要。初回、または依存関係の更新後は、次を実行する。

```sh
pnpm install --frozen-lockfile
```

起動時に Chrome のアプリウィンドウを開く。PWA のインストールや追加の npm 依存は不要。macOS の通常のアプリ配置、Windows の標準インストール先、Linux の PATH 上の `google-chrome` / `google-chrome-stable` を探す。見つからない場合や起動に失敗した場合もサーバーは継続し、手動で開く URL を表示する。別の場所の Chrome は `CHROME_PATH` に実行ファイルのパスを指定する。`pnpm start --no-open` / `pnpm dev --no-open` では自動起動しない。

通常の閲覧に Caddy は不要。`pnpm dev` と開発サーバーの起動・終了テストには、別途 Caddy が必要。macOS で Homebrew を使う場合は次で導入できる。

```sh
brew install caddy
```

## 開発サーバー

ソース変更時に閲覧サーバーを自動再起動する。

```sh
pnpm dev
```

閲覧対象は `content/` にコピーした文書だけ。文書を用意する場合は、先に[コピーの作成手順](usage.md#コピーの管理)を済ませる。コピーがなくても起動できる。

引数なしではコピー内の全 Markdown を再帰的に登録する。起動時の表示範囲を絞るには、コピー内のパスを指定する。これはアクセス制限ではなく、画面からコピー内の別のパスも開ける。Markdown は 1 ファイル 1 MiB、再帰探索は深さ 32 まで。

```sh
# 単独ファイル、またはフォルダーを指定（複数指定可）
pnpm dev content/notes/one.md content/work-notes/two.md
pnpm dev content/notes

# パス引数のフォルダーを再帰的に探す
pnpm dev --recursive content/notes
```

パス引数のフォルダーは、既定では直下だけを探す。引数なしの場合は `--recursive` の有無にかかわらず再帰的に探す。相対 Markdown リンク・画像の許可範囲は、引数なしなら `content/` 全体、フォルダー指定ならその配下、単独ファイル指定なら親フォルダー配下となる。

Caddy の起動完了後、`Dev ready:` の URL を Chrome アプリモードで一度だけ開く。通常は `http://md.localhost:8080`。`--no-open` を指定した場合や Chrome を起動できなかった場合は、表示された URL を手動で開く。Ctrl+C で Caddy と閲覧サーバーの両方を終了する。Chrome は終了しない。Chrome のウィンドウを閉じてもサーバーは止まらない。サーバーとプロキシはループバックだけで待ち受ける。`.localhost` を解決しない環境では、ローカル DNS / hosts の設定が必要。

`src` / `public` の変更で閲覧サーバーを再起動する。Chrome のウィンドウは追加せず、既存の画面を ⌘⇧R / Ctrl+Shift+R で手動で再読み込みする。⌘R / Ctrl+R は表示中の文書だけを再読み込みするため、この用途には使わない。閲覧対象の Markdown の更新は監視の対象ではないため、本文上部の「再読み込み」で反映する。

同じリポジトリで `pnpm dev` を再実行すると、以前このスクリプトが起動した Caddy と閲覧サーバーを終了してから起動する。既存の Caddy 設定や常駐サービスは変更しない。

### 生 HTML を許可する

信頼できるファイルに限り、`pnpm dev --allow-html content/notes/trusted.md` で生 HTML を描画できる。既定では生 HTML を文字として表示し、HTML コメントは非表示にする。アプリが保存する固定形式のマーカーは、許可の有無にかかわらず描画する。

`--allow-html` は、そのサーバーで開くすべての Markdown に適用する。コピー内でも信頼できるファイルだけを開く。スクリプト・フォーム・外部リソースの制限は維持するが、HTML の全機能を安全化する仕組みではない。生 HTML のリンク・画像は、通常の Markdown リンク・画像と同じ処理を通らない。描画に関わる変更では両方のモードを確認する。

### 毎回同じパスを登録する

リポジトリ直下に、Git の対象外となる `dev.local.json` を作成する。この設定ファイルは `pnpm dev` 専用で、`pnpm start` は読まない。

```json
{
  "paths": ["content/notes-one", "content/notes-two"],
  "recursive": false,
  "allowHtml": false
}
```

- `paths` は必須の文字列配列。`content/` 内のフォルダー・Markdown ファイルを混在させられる。空配列ならコピー全体を登録する。以前の外部パスは拒否されるため、コピー後のパスに変更する。
- 起動引数でパスを指定すると、設定ファイルの `paths` を使わず、引数のパスを登録する。
- `recursive: true` は `--recursive`、`allowHtml: true` は `--allow-html` と同じ。**パス引数の有無にかかわらず適用する。** `allowHtml: true` の場合は、そのサーバーで開くすべての Markdown が信頼できることを確認する。
- `recursive` / `allowHtml` を省略した場合は `false`。起動引数のフラグで有効にできるが、設定ファイルの `true` を打ち消す起動フラグはない。

### ポートを変更する

| 環境変数 | 指定なし | `0` を指定 | 固定値を指定 |
| --- | --- | --- | --- |
| `DEV_PORT` | ブラウザーから接続するプロキシは 8080 番を優先し、使用中なら空きポート | 空きポート | 指定したポート |
| `DEV_BACKEND_PORT` | 内部の閲覧サーバーは 3100 番を優先し、使用中なら空きポート | 空きポート | 指定したポート |

```sh
DEV_PORT=8081 DEV_BACKEND_PORT=3101 pnpm dev
DEV_PORT=0 DEV_BACKEND_PORT=0 pnpm dev
```

値は 0〜65535 の整数。固定値で指定したポートが使用中の場合は、自動で別ポートには切り替えない。プロキシと内部サーバーには異なるポートを使う。`PORT` / `VIEWER_ORIGIN` は開発スクリプトが自動設定するため、開発用ポートの変更には使わない。

ポート番号のない HTTP URL が必要で、Caddy が 80 番で待ち受けられる環境では `DEV_PORT=80 pnpm dev` も使える。80 番の待受には環境によって追加権限が必要。スクリプト自体は sudo を実行せず、80 番に自動変更もしない。

## 任意の構成: ポート番号なしのローカル URL

開発スクリプトを使わず、閲覧サーバーと Caddy を別々に起動する構成。付属の `Caddyfile` は `http://md.localhost` を `127.0.0.1:3000` に転送する。Caddy を導入し、80 番で待ち受けられることを確認してから起動する。

```sh
# 先に別のターミナルでプロキシを起動する
caddy run --config ./Caddyfile

# 閲覧サーバーは通常ユーザーで起動する。起動後に Chrome を開く
VIEWER_ORIGIN=http://md.localhost pnpm start
```

閲覧対象は `content/` 内だけで、引数なしなら全 Markdown を再帰的に登録する。文書がなくても起動できる。サーバー再起動後は、既存の画面も ⌘⇧R / Ctrl+Shift+R で再読み込みする。それぞれのターミナルで Ctrl+C を押して終了する。

Caddy はループバックだけで待ち受け、証明書の発行や OS の信頼ストア変更はしない。80 番を既存の Caddy が使用している場合は、その設定にサイトブロックを統合する。別のアプリが使用している場合は競合を解消するか、80 番を使わない開発サーバーの構成を選ぶ。80 番への bind が拒否される環境では、Caddy 側のサービス権限を設定する。閲覧サーバーを管理者権限で起動しない。

`.localhost` はループバック解決するブラウザー向けの名前。環境が解決しない場合はローカル DNS / hosts の設定が必要。

### プロキシの URL を変更する

`VIEWER_ORIGIN` には、ブラウザーで開く HTTP(S) オリジン（スキーム・ホスト・ポート）を指定する。パス・クエリ・フラグメント・認証情報は含めない。設定中は、そのオリジンの Host / Origin だけを受け付けるため、通常の `http://127.0.0.1:3000` による直接アクセスは拒否する。

別の名前やポートに変更する場合は、次を揃える。

- Caddy のサイト名と `VIEWER_ORIGIN` のスキーム・ホスト・ポートを同じにする。
- バックエンドの `PORT` を変更した場合は、Caddy の転送先も変更する。

## 検証

リポジトリ直下で実行する。CLI の起動テストは、一時プロジェクト内のコピー・設定・プロセス記録と模擬 Chrome を使い、利用者の `content/` や稼働中の開発サーバーには触れない。実際の Chrome も起動しない。

```sh
# 静的チェック、サーバー・描画・開発起動のテスト
pnpm check
pnpm test

# 初回、または Playwright 更新後に必要なブラウザーを導入する
pnpm exec playwright install chromium webkit
pnpm test:e2e

# 依存関係の脆弱性を確認する
pnpm audit
```

### 結果を判断する際の注意

- `pnpm test` は一時ディレクトリの実ファイルで検証する。Caddy が見つからない場合、開発サーバーの起動・終了・再起動に関するテストはスキップする。終了コードだけでなく、結果のスキップ件数も確認する。Windows では一部のプロセス制御や特殊ファイルのテストもスキップする。
- E2E テストは Chromium と WebKit を対象にする。画面・選択・iframe を変更した場合は、両方の結果を確認する。Firefox はこのテスト構成に含まない。キーイベントによるテストだけでは、Chrome が予約キーを Viewer に渡すかは検証できない。
- E2E テストはワーカーごとの一時コピー用ディレクトリと空きポートで専用サーバーを起動する。手動起動は不要で、利用者の `content/` は読み書きしない。
- `pnpm audit` は依存関係の監査であり、アプリ自体の安全性を保証するものではない。

変更内容に応じて検証を選び、実行したコマンド、失敗、スキップ、未実施を区別して報告する。ドキュメントのみの変更では、リンク先・コマンド・記述と実装の整合性を確認する。実行していないテストを成功扱いにしない。

### Chrome アプリモードの手動確認

起動・ショートカットを変更した場合は、実際の Chrome でも確認する。確認用のコピーを用意し、`pnpm start` または `pnpm dev` で開いた専用ウィンドウを使う。

- 複数のタブを開き、Shift+クリックで範囲選択して ⌘W / Ctrl+W を押す。選択した Viewer 内のタブだけが閉じること、タブが 0 件でもウィンドウが残ることを確認する。
- Ctrl+Tab / Ctrl+Shift+Tab が Viewer 内の並び順で循環し、スクロール位置を復元することを確認する。Ctrl+@（US 配列では Ctrl+Shift+2）でツリーの検索欄と本文を往復し、本文へ戻った後に Space / PageDown などでスクロールできることも確認する。JIS 配列の @ キーも確認する。ダイアログ表示中や日本語変換中は割り込まない。
- 本文にフォーカスした状態でも、⌘R / Ctrl+R が表示中の文書だけを読み直し、⌘⇧F / Ctrl+Shift+F が Viewer の全画面表示を切り替えることを確認する。Chrome 自体の全画面化ではない。
- 「ショートカットの詳細」は通常のブラウザータブで開き、そのページではキーを上書きしないことを確認する。Viewer 外にフォーカスがある場合も Chrome の操作になる。通常の Chrome タブでは閉じるキーがブラウザーに優先される場合があるため、× ボタンやタブ上の Delete / Backspace も確認する。
- `--no-open` がウィンドウを開かず、開発時のソース変更による再起動がウィンドウを追加しないことを確認する。サーバーと Chrome は別々に終了する。

## 構成と依存の方針

実行時の直接依存は markdown-it のみ。サーバーは Node.js 標準 HTTP、画面はブラウザー API で実装し、ビルドを不要にしている。HTTP のアクセス制御や DOM 操作は、このプロジェクトで保守する。

Markdown パーサーは自作せず、追加プラグインも使わない。依存関係を増やす場合は、必要な機能と保守負担を確認する。

通常起動の許可ルートは `content/` に固定し、変更用の環境変数やフラグは用意しない。`createViewerServer` の `contentDirectory` は、テストで一時ディレクトリを渡すためのプログラム上の設定。HTTP リクエストから変更できないことを維持する。

本文はファイルを選択した時点で読み込む。開いているタブの本文キャッシュは直近 10 タブを残すように削減するが、閉じたタブの本文が一覧側に残る場合があり、全体の保持件数の上限ではない。大量ファイル向けの変更では、閉じたファイルも含む保持量を確認する。

# 開発ガイド

環境の準備、開発サーバーの起動、検証の手順を示す。コマンドはリポジトリ直下で実行する。閲覧サーバーは自分の PC 内だけで利用し、外部には公開しない。閲覧サーバーの起動に管理者権限を使わない。

## 準備

通常の閲覧・開発ともに、Node.js 24 以上と pnpm 10.33.2 が必要。初回、または依存関係の更新後は、次を実行する。

```sh
pnpm install --frozen-lockfile
```

閲覧ウィンドウの自動起動には Chrome を使う。追加の npm パッケージやビルドは不要。Chrome は macOS の通常のアプリ配置、Windows の標準インストール先、Linux の PATH 上の `google-chrome` / `google-chrome-stable` から探す。別の場所に導入した場合は `CHROME_PATH` に実行ファイルのパスを指定する。通常の閲覧は[利用ガイドの起動手順](usage.md#起動)に従い、開発時は次の手順を使う。

## 開発サーバー

ソース変更時に閲覧サーバーを自動再起動する。

```sh
pnpm dev
```

閲覧できるのは `content/` にコピーした文書だけなので、文書を用意する場合は先に[コピーの作成手順](usage.md#コピーの管理)を済ませる。コピーがなくてもサーバーは起動できる。

起動引数と `dev.local.json` のどちらにもパスを指定しなければ、`--recursive` の有無にかかわらず、`content/` 内の全 Markdown を再帰的に一覧登録する。新しいウィンドウやタブでは文書を自動で開かず、トップページを表示する。画面の再読み込みや戻る・進むでは、その画面の履歴からタブを復元する。

起動時に一覧登録する文書を絞るには、コピー内のパスを指定する。これはアクセス制限ではなく、画面からコピー内の別のパスも開ける。Markdown は 1 ファイル 1 MiB、再帰探索は深さ 32 まで。

```sh
# 単独ファイル、またはフォルダーを指定（複数指定可）
pnpm dev content/notes/one.md content/work-notes/two.md
pnpm dev content/notes

# パス引数のフォルダーを再帰的に探す
pnpm dev --recursive content/notes
```

フォルダーを指定した場合は、既定では直下だけを探す。サブフォルダー内も探すには `--recursive` を付ける。Markdown 記法の相対リンク・画像は、その Markdown ファイルがあるフォルダーを基準にパスを解決する。許可範囲は、起動引数・設定ファイルともパス未指定なら `content/` 全体、フォルダー指定ならその配下、単独ファイル指定なら親フォルダー配下となる。

毎回使うパスやフラグを保存する場合は、[共通設定ファイルの作成手順](usage.md#毎回同じパスと設定で起動する)を済ませる。`dev.local.json` は `pnpm start` / `pnpm dev` の両方で読み込む。パス引数は設定ファイルの `paths` より優先し、設定ファイルのフラグはパス引数の有無にかかわらず適用する。特に `allowHtml: true` は通常起動も含め、そのサーバーで開くすべての Markdown に適用するため、信頼できるファイルだけを開く。

閲覧サーバーの起動が完了すると、`Dev ready:` に表示された URL（通常は `http://127.0.0.1:8080`）の閲覧ウィンドウが開く。macOS ではその URL 用にインストール済みの Viewer アプリを優先し、それ以外は Chrome アプリモードを使う。`--no-open` を指定した場合や、Chrome が見つからないなどの理由で自動起動に失敗した場合も、サーバーは起動したまま URL を表示する。表示された URL は手動で開ける。

起動したターミナルで Ctrl+C を押すと閲覧サーバーが終了するが、Chrome は終了しない。逆に、Chrome のウィンドウを閉じてもサーバーは止まらない。サーバーは `127.0.0.1` だけで待ち受け、プロキシやローカル DNS の設定は不要。

`src` / `public` のファイルを変更すると閲覧サーバーが再起動する。Chrome のウィンドウは追加で開かないため、既存の画面を ⌘⇧R / Ctrl+Shift+R で手動で再読み込みする。⌘R / Ctrl+R は表示中の文書だけを再読み込みするため、この用途には使わない。閲覧対象の Markdown の更新は監視の対象ではないため、本文上部の「再読み込み」で反映する。

macOS / Linux では、同じリポジトリで `pnpm dev` を再実行すると、以前このスクリプトが起動した閲覧サーバーを終了してから起動する。Windows では、以前のサーバーを先に Ctrl+C で終了する。

### 通常の Chrome と別アプリにする（macOS）

Dock と ⌘Tab で通常の Chrome と分けるには、初回に [Viewer アプリのインストール手順](usage.md#macos-で通常の-chrome-と分ける)を済ませる。開発時は `DEV_PORT=8080 pnpm dev` で URL を `http://127.0.0.1:8080` に固定して登録する。以後は同じ URL で起動すると専用アプリが開く。サーバーは引き続き必要で、ソース変更後はアプリ内でも ⌘⇧R で画面全体を再読み込みする。

アプリは `~/Applications/Chrome Apps.localized/` と `/Applications/Chrome Apps.localized/` から探す。URL はホスト名・ポートまで一致する必要があり、ポートの自動変更で別の URL になれば Chrome アプリモードに戻る。通常起動の `http://127.0.0.1:3000` は別の登録になる。登録を削除するには Chrome の `chrome://apps` からアンインストールする。

移動済みのアプリを指定するには、`VIEWER_APP_PATH` に `.app` の絶対パスを設定する。アプリの読み取り・起動に失敗した場合や登録 URL が違う場合はエラーを表示し、別アプリや Chrome を代わりに開かない。`CHROME_PATH` だけを指定すると自動探索せず、その Chrome をアプリモードで開く。両方を指定した場合は `VIEWER_APP_PATH` を優先する。`--no-open` はどちらも自動起動しない。

マニフェストとアプリアイコンは固定のローカル資産として配信する。Service Worker は登録せず、文書のオフラインキャッシュも追加しない。アプリをインストールしても、コピー内の文書だけを閲覧・保存する制限は変えない。

### 案内を非表示にする

`pnpm dev --no-notices` で起動すると、ショートカット・コピー閲覧・トップページの操作案内の通知を最初から非表示にできる。通常起動では `pnpm start --no-notices` を使う。トップページ本体の説明は残り、読み込み中・操作結果・エラーは引き続き通知する。ショートカットの詳細は「コマンドパレット」から開ける。案内の通知は既定では表示し、このうちショートカットとコピー閲覧の案内は、それぞれ × で閉じると画面全体を再読み込みするまで再表示しない。

### 生 HTML を許可する

信頼できるファイルに限り、`pnpm dev --allow-html content/notes/trusted.md` で生 HTML を描画できる。既定では生 HTML を文字として表示し、HTML コメントは非表示にする。アプリが保存する固定形式のマーカーは、許可の有無にかかわらず描画する。

`--allow-html` と設定ファイルの `allowHtml: true` は、そのサーバーで開くすべての Markdown に適用する。コピー内でも信頼できるファイルだけを開く。スクリプト・フォーム・外部リソースの制限は維持するが、任意の HTML を安全に表示できることは保証しない。

文書間の移動や画像表示には Markdown 記法を使う。生 HTML のリンク・画像は、通常の Markdown リンク・画像と同じ処理を通らない。生 HTML の相対リンクはアプリ内タブで開かず、`<img>` の相対パス画像も読み込まない。描画に関わる変更では両方のモードを確認する。

### ポートを変更する

`DEV_PORT` は 0〜65535 の整数。未指定なら 8080 番を優先し、使用中なら空きポートを選ぶ。`0` を指定した場合も空きポートを選ぶ。固定値で指定したポートが使用中の場合は、自動で別ポートには切り替えない。開発用ポートの変更には `PORT` ではなく `DEV_PORT` を使う。

```sh
DEV_PORT=8081 pnpm dev
DEV_PORT=0 pnpm dev
```

環境変数を付けるコマンド例は macOS / Linux のシェル用。Windows の PowerShell では `$env:DEV_PORT = "8081"; pnpm dev` と指定する。設定はその PowerShell セッションに残るため、終了後に `Remove-Item Env:DEV_PORT` で解除する。`CHROME_PATH` なども同じ方法で指定する。

以前の構成から更新する場合は、起動中の開発サーバーと Caddy を先に停止する。Caddy の導入・起動と `DEV_BACKEND_PORT` は不要となる。`VIEWER_ORIGIN` を設定していた場合は解除し、表示された `127.0.0.1` の URL を使う。旧 `md.localhost` 用の Viewer アプリは新しい URL では起動しないため、専用アプリを使う場合は新しい URL でインストールし直す。

## 検証

リポジトリ直下で実行する。CLI の起動テストは、一時プロジェクト内のコピー・設定・プロセス記録と、Chrome の代わりに動くテスト用プログラムを使う。利用者の `content/` や稼働中の開発サーバーには触れず、実際の Chrome も起動しない。

```sh
# 静的チェック、サーバー・描画・開発起動のテスト
pnpm check
pnpm test

# 初回、または Playwright 更新後に必要なブラウザーを導入する
pnpm exec playwright install chromium webkit
pnpm test:e2e

# 依存関係の脆弱性を確認する
pnpm audit
```

### 結果を判断する際の注意

- `pnpm test` は一時ディレクトリの実ファイルで検証する。追加のプロキシは不要。Windows では一部のプロセス制御や特殊ファイルのテストをスキップするため、終了コードだけでなく、結果のスキップ件数も確認する。
- E2E テストは Chromium と WebKit を対象にする。画面・選択・iframe を変更した場合は、両方の結果を確認する。Firefox はこのテスト構成に含まない。キーイベントによるテストだけでは、Chrome が予約キーを Viewer に渡すかは検証できない。
- E2E テストはワーカーごとの一時コピー用ディレクトリと空きポートで専用サーバーを起動する。手動起動は不要で、利用者の `content/` は読み書きしない。
- `pnpm audit` は依存関係の監査であり、アプリ自体の安全性を保証するものではない。

変更内容に応じて検証を選び、実行したコマンド、失敗、スキップ、未実施を区別して報告する。ドキュメントのみの変更では、リンク先と見出しアンカーが有効か、コマンドと記述が実装に合っているかを確認する。実行していないテストを成功扱いにしない。

### Chrome アプリモードの手動確認

起動・ショートカットを変更した場合は、実際の Chrome でも確認する。確認用のコピーを用意し、`pnpm start` または `pnpm dev` で開いた専用ウィンドウを使う。

- 複数のタブを開き、Shift+クリックで範囲選択して ⌘W / Ctrl+W を押す。選択した Viewer 内のタブだけが閉じること、タブが 0 件でもウィンドウが残ることを確認する。
- Ctrl+Tab / Ctrl+Shift+Tab が Viewer 内の並び順で循環し、スクロール位置を復元することを確認する。Ctrl+@（US 配列では Ctrl+Shift+2）でツリーの検索欄と本文を往復し、本文へ戻った後に Space / PageDown などでスクロールできることも確認する。JIS 配列の @ キーも確認する。ダイアログ表示中や日本語変換中は割り込まない。
- 本文にフォーカスした状態でも、⌘R / Ctrl+R が表示中の文書だけを読み直し、⌘⇧F / Ctrl+Shift+F が Viewer の全画面表示を切り替えることを確認する。Chrome 自体の全画面化ではない。
- ⌘B / Ctrl+B がサイドバーを切り替え、⌘P / Ctrl+P がパレット、⌘⇧V / Ctrl+Shift+V が Raw / Preview、⌘⇧T / Ctrl+Shift+T が Viewer 内の閉じたタブの復元になることを確認する。⌘F / Ctrl+F、⌘G / Ctrl+G、⌘⇧G / Ctrl+Shift+G が本文だけを検索し、Chrome の検索や印刷・タブ復元にならないことも確認する。
- 「ショートカットの詳細」は通常のブラウザータブで開き、そのページではキーを上書きしないことを確認する。Viewer 外にフォーカスがある場合も Chrome の操作になる。通常の Chrome タブでは閉じるキーがブラウザーに優先される場合があるため、× ボタンやタブ上の Delete / Backspace も確認する。
- macOS では固定 URL で一度インストールした Viewer が通常の Chrome とは別の Dock / ⌘Tab の項目になること、同じ URL ではインストール済みアプリを起動し、別の URL では誤って既存アプリを開かないことを確認する。確認には一時プロファイルを使い、既存の Chrome の登録やデータは変更しない。
- `--no-open` がウィンドウを開かず、開発時のソース変更による再起動がウィンドウを追加しないことを確認する。サーバーと Chrome は別々に終了する。

## 構成と依存の方針

- `public/scripts/` はブラウザー用 JavaScript、`public/styles/` は CSS。HTML とマニフェストは `public/` 直下、フォントとライセンスは `public/fonts/`、アイコンは `public/icons/` に置く。
- `src/` は文書の読み書き・描画・HTTP、`src/runtime/` は起動設定の読み込みや OS・ブラウザーの起動処理を担当する。
- `tests/unit/` は単体テスト、`tests/integration/` はファイル・HTTP・プロセスを使う結合テスト、`tests/playwright/` はブラウザー E2E。共通のテスト支援は `tests/helpers/` に置く。

`public/scripts/app.js` は文書・タブ・履歴と非同期処理の採否を管理し、各 UI モジュールには表示に必要なデータと操作を渡す。本文の iframe・イベント・Blob URL は `reader.js` と `highlight-toolbar.js` で破棄まで管理する。本文用のスクリプトを iframe に読み込ませる構成にはしない。読み込み表示は本文領域内に重ね、読み込みの開始・終了だけで画面上部の通知領域の高さを変えない。

配信する URL と物理的な配置は `src/server.mjs` の許可リストで対応付ける。配置を変えても公開 URL を不用意に変更せず、ディレクトリ全体を公開しない。`theme.js` は初期配色を適用するため、スタイルとアプリの初期化より前に読み込む。

実行時の直接依存は markdown-it のみ。UI・Preview 用の BIZ UDPゴシックと Raw・コード用の BIZ UDゴシックは、通常・太字の WOFF2 を `public/fonts/` に SIL Open Font License 1.1 と一緒に同梱する。更新時は[同梱フォントの更新手順](../public/fonts/README.md)に従う。起動・テスト時のフォント変換は不要。フォント・SVG はローカル配信し、CDN は使わない。

同梱フォントの URL には配信時に内容ハッシュを付け、そのハッシュが一致するリクエストだけブラウザーの長期キャッシュを許可する。文書・API・CSS など、それ以外の応答は `no-store` を維持する。本文 iframe はフォントの読み込みとスクロール位置の復元が終わるまで非表示にし、代替フォントでの途中描画を見せない。

サーバーは Node.js 標準 HTTP、画面はブラウザー API で実装し、ビルドを不要にしている。HTTP のアクセス制御や DOM 操作は、このプロジェクトで保守する。

Markdown パーサーは自作せず、追加プラグインも使わない。依存関係を増やす場合は、必要な機能と保守負担を確認する。

通常起動の許可ルートは `content/` に固定し、変更用の環境変数やフラグは用意しない。`createViewerServer` の `contentDirectory` は、テストで一時ディレクトリを渡すためのプログラム上の設定。HTTP リクエストから変更できないことを維持する。

「まとめて開く」では、登録済み文書のタブを追加し、本文はそのタブを表示したときに読み込む。タブが一つも開いていない場合だけ、最初の検索結果の本文を読み込む。開いているタブの本文キャッシュは直近に表示した 10 タブ分を残すが、閉じたタブの本文がファイル一覧のデータに残る場合もあるため、アプリ全体で保持する本文の数の上限ではない。大量ファイル向けの変更では、閉じたファイルも含めてメモリー使用量を確認する。

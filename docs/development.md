# 開発ガイド

必要環境、開発起動、ローカルプロキシ、検証手順を説明します。コマンドはリポジトリ直下で実行します。閲覧操作は[利用ガイド](usage.md)、保守時に維持する防御は[安全設計](security.md)を参照してください。

## 準備

通常の閲覧・開発ともに、Node.js 24 以上と pnpm 10.33.2 が必要です。初回、または依存関係の更新後は、次を実行してください。

```sh
pnpm install --frozen-lockfile
```

通常の閲覧に Caddy は不要です。`pnpm dev` と開発サーバーの起動・終了テストには、別途 Caddy が必要です。macOS で Homebrew を使う場合は次で導入できます。

```sh
brew install caddy
```

Caddy を使わない通常の起動は [README の起動手順](../README.md#起動)を参照してください。ソース変更時に自動再起動するには、以下の開発サーバーを使います。

## 開発サーバー

```sh
pnpm dev
```

先に[コピーの管理](usage.md#コピーの管理)に従って文書を `content/` にコピーしてください。引数なしではコピー内の全 Markdown を再帰的に登録します。表示範囲の指定と探索のフラグは[起動オプション](usage.md#起動オプション)、生 HTML の許可は[利用条件と起動方法](usage.md#生-html-を表示する場合)を参照し、`pnpm start` を `pnpm dev` に置き換えてください。ポートは `PORT` ではなく、[開発用の環境変数](#ポートを変更する)で変更します。

表示された `Dev ready:` の URL を開いてください。通常は `http://md.localhost:8080` です。ブラウザーを自動では開きません。Ctrl+C で Caddy と閲覧サーバーの両方を終了します。

`src` / `public` の変更で閲覧サーバーを再起動します。ブラウザーは手動で再読み込みしてください。閲覧対象の Markdown の更新はこの監視の対象ではないため、本文上部の「再読み込み」で反映します。

同じリポジトリで `pnpm dev` を再実行すると、以前このスクリプトが起動した Caddy と閲覧サーバーを終了してから起動します。既存の Caddy 設定や常駐サービスは変更しません。開発サーバーとプロキシはループバックだけで待ち受けます。

### 毎回同じパスを登録する

リポジトリ直下に、Git の対象外となる `dev.local.json` を作成します。この設定ファイルは `pnpm dev` 専用で、`pnpm start` は読みません。

```json
{
  "paths": ["content/notes-one", "content/notes-two"],
  "recursive": false,
  "allowHtml": false
}
```

- `paths` は必須の文字列配列です。`content/` 内のフォルダー・Markdown ファイルを混在させられます。空配列ならコピー全体を登録します。以前の外部パスは拒否されるため、コピー後のパスに変更してください。
- 起動引数でパスを指定すると、設定ファイルの `paths` を使わず、引数のパスを登録します。
- `recursive: true` は `--recursive`、`allowHtml: true` は `--allow-html` と同じです。**パス引数の有無にかかわらず適用します。**
- `recursive` / `allowHtml` を省略した場合は `false` です。起動引数のフラグで有効にできますが、設定ファイルの `true` を打ち消す起動フラグはありません。

### ポートを変更する

| 環境変数 | 指定なし | `0` を指定 | 固定値を指定 |
| --- | --- | --- | --- |
| `DEV_PORT` | 公開側は 8080 番を優先し、使用中なら空きポート | 空きポート | 指定したポート |
| `DEV_BACKEND_PORT` | 内部側は 3100 番を優先し、使用中なら空きポート | 空きポート | 指定したポート |

```sh
DEV_PORT=8081 DEV_BACKEND_PORT=3101 pnpm dev
DEV_PORT=0 DEV_BACKEND_PORT=0 pnpm dev
```

固定値で指定したポートが使用中の場合は、自動で別ポートには切り替えません。公開側と内部側には異なるポートを使ってください。`PORT` / `VIEWER_ORIGIN` は開発スクリプトが自動設定します。

ポート番号のない HTTP URL が必要で、Caddy が 80 番で待ち受けられる環境では `DEV_PORT=80 pnpm dev` も使えます。80 番の待受には環境によって追加権限が必要です。スクリプト自体は sudo を実行せず、80 番に自動変更もしません。

## 任意の構成: ポート番号なしのローカル URL

開発スクリプトを使わず、閲覧サーバーと Caddy を別々に起動する構成です。付属の [Caddyfile](../Caddyfile) は `http://md.localhost` を `127.0.0.1:3000` に転送します。[準備](#準備)で Caddy を導入し、80 番で待ち受けられることを確認してください。

```sh
# 閲覧サーバーは通常ユーザーで起動する
VIEWER_ORIGIN=http://md.localhost pnpm start

# 別のターミナルで実行する
caddy run --config ./Caddyfile
```

Caddy はループバックだけで待ち受け、証明書の発行や OS の信頼ストア変更はしません。80 番を既存の Caddy が使用している場合は、その設定にサイトブロックを統合してください。別のアプリが使用している場合は競合を解消するか、80 番を使わない開発サーバーの構成を選んでください。80 番への bind が拒否される環境では、Caddy 側のサービス権限を設定する必要があります。閲覧サーバーを管理者権限で起動しないでください。

`.localhost` はループバック解決するブラウザー向けの名前です。環境が解決しない場合はローカル DNS / hosts の設定が必要です。

### プロキシの URL を変更する

`VIEWER_ORIGIN` には、ブラウザーで開く HTTP(S) オリジン（スキーム・ホスト・ポート）を指定します。パス・クエリ・フラグメント・認証情報は含めないでください。設定中は、そのオリジンの Host / Origin だけを受け付けるため、通常の `http://127.0.0.1:3000` による直接アクセスは拒否します。

別の名前やポートに変更する場合は、次を揃えてください。

- Caddy のサイト名と `VIEWER_ORIGIN` のスキーム・ホスト・ポートを同じにする。
- バックエンドの `PORT` を変更した場合は、Caddy の転送先も変更する。

## 検証

リポジトリ直下で実行します。開発サーバーが起動中の場合は、先に[結果を判断する際の注意](#結果を判断する際の注意)を確認してください。

```sh
# 静的チェック、サーバー・描画・開発起動のテスト
pnpm check
pnpm test

# 初回、または Playwright 更新後に必要なブラウザーを導入する
pnpm exec playwright install chromium webkit
pnpm test:e2e

# 依存関係の脆弱性を確認する
pnpm audit
```

### 結果を判断する際の注意

- `pnpm test` は一時ディレクトリの実ファイルで検証します。Caddy が見つからない場合、開発サーバーの起動・終了・再起動に関するテストはスキップします。終了コードだけでなく、結果のスキップ件数も確認してください。Windows では一部のプロセス制御や特殊ファイルのテストもスキップします。
- 開発起動のテストは、同じリポジトリで以前起動した `pnpm dev` を終了させることがあります。作業中の開発サーバーは先に停止してください。
- E2E テストは Chromium と WebKit を対象にします。画面・選択・iframe を変更した場合は、両方の結果を確認してください。Firefox はこのテスト構成に含みません。
- E2E テストはワーカーごとの一時コピー用ディレクトリと空きポートで専用サーバーを起動します。手動起動は不要で、利用者の `content/` は読み書きしません。
- `pnpm audit` は依存関係の監査であり、アプリ自体の安全性を保証するものではありません。

変更内容に応じて検証を選び、実行したコマンド、失敗、スキップ、未実施を区別して報告してください。ドキュメントのみの変更では、リンク先・コマンド・記述と実装の整合性を確認します。実行していないテストを成功扱いにしないでください。

## 構成と依存の方針

実行時の直接依存は markdown-it のみです。サーバーは Node.js 標準 HTTP、画面はブラウザー API で実装し、ビルドを不要にしています。HTTP のアクセス制御や DOM 操作は、このプロジェクトで保守します。

Markdown パーサーは自作せず、追加プラグインも使いません。依存関係を増やす場合は、必要な機能と保守負担を確認してください。

`scripts/copy-docs.mjs` が元文書から独立したコピーを作り、閲覧サーバーは `content/` 内だけを扱います。通常起動でコピー先を変更する環境変数やフラグは用意しません。`createViewerServer` の `contentDirectory` は、テストで一時ディレクトリを渡すためのプログラム上の設定です。HTTP リクエストから変更できないことを維持してください。

本文はファイルを選択した時点で読み込みます。開いているタブの本文キャッシュは直近 10 タブを残すように削減しますが、閉じたタブの本文が一覧側に残る場合があり、全体の保持件数の上限ではありません。大量ファイル向けの変更では、閉じたファイルも含む保持量を確認してください。

# 安全設計

このページは保守者向けに、防御の前提と変更時に維持する条件を説明します。利用者向けの操作・制限は[利用ガイド](usage.md)、ローカルプロキシの設定は[開発ガイドのプロキシ構成](development.md#任意の構成-ポート番号なしのローカル-url)、検証方法は[検証手順](development.md#検証)を参照してください。

## 利用上の前提

ローカルの本人利用を対象にします。閲覧サーバーとリバースプロキシはループバックだけで待ち受け、外部公開しないでください。閲覧サーバーは通常ユーザーの権限で起動します。

別サイトからのローカルファイル操作や、Markdown を通じたスクリプト実行・外部リソース取得を制限します。一方、同じ OS ユーザー権限で動く悪意あるプロセス、ブラウザー拡張、OS 自体の侵害を防ぐ仕組みではありません。脆弱性やバグが一切ないことを保証するものではありません。

## HTTP のアクセス制御

- 閲覧サーバーは `127.0.0.1` で待ち受けます。Host / Origin / Fetch Metadata を検査し、別サイトからの操作を拒否します。
- API には起動ごとのランダムトークンが必要です。トークンはページに埋め込み、リクエストヘッダーで受け付けます。
- `VIEWER_ORIGIN` 未指定時は、待受ポートの `127.0.0.1` / `localhost` を Host として許可します。
- `VIEWER_ORIGIN` 指定時は、検証済みのオリジンだけを許可の根拠にします。任意の Host や転送ヘッダーを信頼しないでください。設定条件と直接アクセスへの影響は[開発ガイドのプロキシ URL 設定](development.md#プロキシの-url-を変更する)を参照してください。
- 静的配信は登録したファイルに限定し、任意のパスを配信しません。API のメソッド、JSON の形式・サイズも検査します。

## ファイルの参照・書き込み

### コピーの作成

コピーは `scripts/copy-docs.mjs` から明示的に行い、閲覧 API から元文書のコピーを実行しません。Markdown と対応画像だけを読み、バイト列を新規ファイルに書き込みます。シンボリックリンク・特殊ファイル・元ファイルの権限情報は引き継ぎません。ハードリンクも新規ファイルになるため、コピーへの変更は元ファイルに伝わりません。

既存コピーの上書きは禁止し、コピー元とコピー先が互いに包含する配置も拒否します。サイズ・深さの上限を維持し、失敗時には新規作成したコピーだけを後始末してください。コピー先ルート自体がシンボリックリンクの場合も拒否します。

### 読み取り

通常起動では、このリポジトリの `content/` を固定の許可ルートにします。HTTP リクエストや起動パス引数で許可ルートを変更してはいけません。パス入力・起動引数・履歴復元は、解決前のパスと実パスの両方を検証し、コピー外への参照を拒否します。履歴から渡される `root` も信頼せず、コピー内かを検証します。

登録する文書の相対参照ルートも必ずコピー内に収めます。本文の再読み取り、相対 Markdown リンク、画像取得、マーカー保存では実パスを再確認し、登録後に外部へのシンボリックリンクに置き換えられた場合も拒否します。通常ファイルの確認とサイズ制限を行い、読み取り中にサイズが増えた場合も上限を適用します。

フォルダー探索では範囲外への参照を検査し、シンボリックリンクをスキップします。ブラウザー選択・ドロップによる取り込みと任意文字列を描画する `/api/render` は廃止しました。現在の制限は[利用ガイド](usage.md#対応範囲と制限)を参照してください。

これはアプリのアクセス制限であり、OS のサンドボックスではありません。同じユーザー権限を持つ悪意あるプロセスによる同時差し替え、手動で追加されたハードリンク等まで隔離する保証はありません。`content/` の管理者はリンクを追加せず、コピー用スクリプトを利用してください。

### マーカーの書き込み

書き込み API は、コピー内の登録済み Markdown に固定形式のマーカーを追加・色変更・削除する操作だけを受け付けます。コピー元は書き込み先にしません。

保守時は次の検証を維持してください。

- 登録済みのファイル ID から対象を特定し、書き込み先として任意のパスや本文を受け付けない。登録元のルートが必ずコピー内にある条件を維持する。
- 選択範囲、選択文字列、許可した色・マーカー形式を検証する。
- ファイル内容のハッシュで変更競合を検出し、Markdown の描画構造を壊す変更を拒否する。
- 更新後のサイズにも Markdown の上限を適用する。
- 同じフォルダーに一時ファイルを作り、置換前に対象ファイルの同一性と内容を再確認する。失敗時は一時ファイルを後始末する。

シンボリックリンクを作成する書き込みは行いません。これらは、同じ OS ユーザー権限を持つ悪意あるプロセスに対する完全な競合防御を保証するものではありません。

## Markdown・HTML の描画

### 既定の描画

既定では markdown-it の `html: false` を維持します。HTML コメントの除去や、マーカー用の完全一致する 5 色の `mark` タグの描画を変更する場合も、任意の生 HTML を有効にしないでください。

Markdown のリンク・画像 URL は、描画時点では無効な属性に移します。その後、親ページがリンク先や相対画像を扱います。外部画像・絶対パス画像は読み込まず、ローカル画像の形式とサイズを検査します。HTML / SVG を画像として配信しません。

### 生 HTML を許可した場合

生 HTML のリンクや属性は、Markdown のリンク・画像向けの無効化処理を通りません。本文の CSP は維持しますが、通常の Markdown リンク・画像と同じ扱いになるとはみなさないでください。描画方式や対応範囲を変更する場合は、既定モードと HTML 許可モードの両方を確認してください。

## 本文 iframe の CSP と sandbox

本文は iframe に表示し、親画面とは別の厳しい CSP を適用します。本文の `script-src 'none'` と `form-action 'none'` を維持し、外部リソースの取得を禁止します。本文用スタイルは同一オリジンから読み、許可した画像は Blob URL で表示します。

sandbox には `allow-scripts` と `allow-same-origin` を含めています。WebKit で、親ページが本文に登録したイベントを動作させるための設定です。**sandbox の `allow-scripts` は本文スクリプトの許可を意味しません。本文 CSP の `script-src 'none'` を緩めないでください。**

iframe・HTML 描画・イベント処理を変更する場合は、操作が動くことに加え、スクリプトとイベント属性の実行が CSP によって拒否されることを確認してください。対象ブラウザーと実行方法は[開発ガイドの検証手順](development.md#検証)を参照してください。

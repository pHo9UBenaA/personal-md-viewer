# 安全設計

保守者向けに、防御の前提と変更時に維持する条件を示す。

## 利用上の前提

ローカルの本人利用を対象とする。閲覧サーバーとリバースプロキシはループバックだけで待ち受け、外部公開しない。閲覧サーバーは通常ユーザーの権限で起動する。

別サイトからのローカルファイル操作や、Markdown を通じたスクリプト実行・外部リソース取得を制限する。一方、同じ OS ユーザー権限で動く悪意あるプロセス、ブラウザー拡張、OS 自体の侵害を防ぐ仕組みではない。脆弱性やバグが一切ないことを保証するものではない。

## Chrome の起動

CLI は起動完了後に、ローカルの閲覧 URL を Chrome の `--app` 引数で開く。Chrome の実行ファイルは標準配置かローカルの `CHROME_PATH` から選び、HTTP から起動先や引数を指定する API は設けない。シェルを介さず、ブラウザーのセキュリティ機能を無効化する引数は追加しない。Chrome のプロファイル設定も変更しない。アプリモードでも、本文の CSP・sandbox とコピー内へのアクセス制限を維持する。

## HTTP のアクセス制御

- 閲覧サーバーは `127.0.0.1` で待ち受ける。Host / Origin / Fetch Metadata を検査し、別サイトからの操作を拒否する。
- API には起動ごとのランダムトークンが必要。トークンはページに埋め込み、リクエストヘッダーで受け付ける。
- `VIEWER_ORIGIN` 未指定時は、待受ポートの `127.0.0.1` / `localhost` を Host として許可する。
- `VIEWER_ORIGIN` 指定時は、検証済みのオリジンの Host / Origin だけを許可する。HTTP(S) のスキーム・ホスト・ポートのみを受け付け、パス・クエリ・フラグメント・認証情報は拒否する。設定したオリジンと異なるバックエンド URL への直接アクセスも拒否する。任意の Host や転送ヘッダーを信頼しない。
- 静的配信は登録したファイルに限定し、任意のパスを配信しない。SVG は固定の UI 資産だけを配信し、親画面で同一オリジンの画像を許可する。フォントも配信先を登録した同梱ファイルだけとし、親画面・本文 iframe の `font-src` は同一オリジンに限定する。本文 iframe の画像は引き続き Blob URL に限定し、文書中の SVG を画像として配信しない。API は POST のみを受け付け、JSON の形式と 2 MiB のサイズ上限を検査する。

## ファイルの参照・書き込み

### コピーの作成

コピーは `scripts/copy-docs.mjs` から明示的に行い、閲覧 API から元文書のコピーを実行しない。`.md` / `.markdown` と PNG / JPEG / GIF / WebP / AVIF だけを読み、バイト列を新規ファイルに書き込む。シンボリックリンク・特殊ファイル・元ファイルの権限情報は引き継がない。ハードリンクも新規ファイルになるため、コピーへの変更は元ファイルに伝わらない。

既存コピーの上書きは禁止し、コピー元とコピー先ルートが互いに包含する配置も拒否する。コピー先ルート自体がシンボリックリンクの場合も拒否する。Markdown は 1 ファイル 1 MiB、画像は 1 ファイル 5 MiB、深さは 32 までに制限する。コピー失敗時は、新規作成したコピーだけを削除する。

### 読み取り

通常起動では、このリポジトリの `content/` を固定の許可ルートにする。HTTP リクエストや起動パス引数で許可ルートを変更してはいけない。パス入力・起動引数・履歴復元は、解決前のパスと実パスの両方を検証し、コピー外への参照を拒否する。履歴から渡される `root` も信頼せず、コピー内かを検証する。

登録する文書の相対参照ルートも必ずコピー内に収める。本文の再読み取り、相対 Markdown リンク、画像取得、マーカー保存では実パスを再確認し、登録後に外部へのシンボリックリンクに置き換えられた場合も拒否する。通常ファイルの確認と、Markdown 1 MiB・画像 5 MiB のサイズ制限を行い、読み取り中にサイズが増えた場合も上限を適用する。

フォルダー探索では範囲外への参照を検査し、深さ 32 の上限を適用する。`.git` / `node_modules` / `.DS_Store` とシンボリックリンクをスキップする。ブラウザー選択・ドロップによる取り込みや、任意文字列を描画する API は設けない。

ファイル件数、登録総数、探索項目数、コピーの合計サイズには固定上限がない。大量ファイルを扱う変更では、ディスク容量・探索時間・メモリー使用量を確認する。

ファイルの保護はアプリのアクセス制限であり、OS のサンドボックスではない。同じユーザー権限を持つ悪意あるプロセスによる同時差し替え、手動で追加されたハードリンク等まで隔離する保証はない。`content/` の管理者はリンクを追加せず、コピー用スクリプトを利用する。

### マーカーの書き込み

書き込み API は、コピー内の登録済み Markdown に固定形式のマーカーを追加・色変更・削除する操作だけを受け付ける。コピー元は書き込み先にしない。

保守時は次の検証を維持する。

- 登録済みのファイル ID から対象を特定し、書き込み先として任意のパスや本文を受け付けない。登録元のルートが必ずコピー内にある条件を維持する。
- 選択範囲、選択文字列、許可した色・マーカー形式を検証する。
- ファイル内容のハッシュで変更競合を検出し、Markdown の描画構造を壊す変更を拒否する。
- 更新後のサイズにも Markdown の上限を適用する。
- 同じフォルダーに一時ファイルを作り、置換前に対象ファイルの同一性と内容を再確認する。失敗時は一時ファイルを削除する。

シンボリックリンクを作成する書き込みは行わない。書き込み時の検証は、同じ OS ユーザー権限を持つ悪意あるプロセスに対する完全な競合防御を保証するものではない。

## Markdown・HTML の描画

### 既定の描画

既定では markdown-it の `html: false` を維持する。HTML コメントの除去や、マーカー用の完全一致する 5 色の `mark` タグの描画を変更する場合も、任意の生 HTML を有効にしない。

Markdown のリンク・画像 URL は、描画時点では無効な属性に移す。その後、親ページがリンク先や相対画像を扱う。外部画像・絶対パス画像は読み込まず、ローカル画像の形式とサイズを検査する。HTML / SVG を画像として配信しない。画像は 1 ページ 100 件まで読み込む。

### 生 HTML を許可した場合

`--allow-html` はサーバー全体に適用されるため、信頼できる Markdown だけを対象とする。スクリプト・フォーム・外部リソースの制限は維持するが、HTML の全機能を安全化する仕組みではない。

生 HTML のリンクや属性は、Markdown のリンク・画像向けの無効化処理を通らない。本文の CSP は維持するが、通常の Markdown リンク・画像と同じ扱いになるとはみなさない。描画方式や対応範囲を変更する場合は、既定モードと HTML 許可モードの両方を確認する。

本文検索は DOM のテキストから一致箇所を求め、CSS Highlights で現在位置を強調する。文字列を HTML として挿入したり、マーカー用に対応付けたテキストノードを書き換えたりしない。検索語はサーバーへ送らず、文書にも保存しない。

## 本文 iframe の CSP と sandbox

本文は iframe に表示し、親画面とは別の厳しい CSP を適用する。本文の `script-src 'none'` と `form-action 'none'` を維持し、外部リソースの取得を禁止する。本文用スタイルは同一オリジンから読み、許可した画像は Blob URL で表示する。

sandbox には `allow-scripts` と `allow-same-origin` を含めている。WebKit で、親ページが本文に登録したイベントを動作させるための設定。**sandbox の `allow-scripts` は本文スクリプトの許可を意味しない。本文 CSP の `script-src 'none'` を緩めない。**

iframe・HTML 描画・イベント処理を変更する場合は、Chromium と WebKit の両方で操作が動くことに加え、スクリプトとイベント属性の実行が CSP によって拒否されることを確認する。

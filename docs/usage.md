# 利用ガイド

`content/` にコピーした Markdown を閲覧し、マーカーを保存するための手順を示す。サーバーは自分の PC 内だけで利用し、外部には公開しない。コマンドはリポジトリ直下で実行する。

## 起動

初回、または依存関係の更新後は、[必要環境と依存関係の準備](development.md#準備)を済ませる。

```sh
# Markdown と対応画像だけを content/notes/ にコピーする
pnpm copy-docs "/Users/you/Documents/notes"
pnpm start
```

Markdown は 1 ファイル 1 MiB、対応画像は 1 ファイル 5 MiB、フォルダーは深さ 32 までコピーできる。既存の同名コピーは上書きしない。コピーと元ファイルは同期せず、マーカーはコピーだけに保存する。

起動すると閲覧ウィンドウが自動で開く。macOS では、その URL 用にインストールした Markdown Viewer アプリを優先し、未インストールなら Chrome アプリモードで開く。Windows / Linux は Chrome アプリモードを使う。Chrome が見つからない場合や自動起動に失敗した場合も、サーバーは起動したまま URL（既定は `http://127.0.0.1:3000`）を表示する。Chrome を導入するか、表示された URL を手動で開く。macOS では通常のアプリ配置、Windows では標準のインストール先、Linux では PATH 上の `google-chrome` / `google-chrome-stable` を探す。別の場所に導入した場合は `CHROME_PATH` に実行ファイルのパスを指定する。

サーバーは管理者権限を使わずに起動し、`127.0.0.1` だけで待ち受ける。終了するには、起動したターミナルで Ctrl+C を押す。Chrome のウィンドウを閉じてもサーバーは止まらず、サーバーを終了しても Chrome は閉じない。サーバーを再起動した後は、既存のウィンドウも ⌘⇧R / Ctrl+Shift+R で再読み込みする。

起動引数と `dev.local.json` のどちらにもパスを指定しなければ、`content/` 配下の Markdown を再帰的に一覧登録する。新しいウィンドウやタブでは、起動パスの指定にかかわらずトップページを表示し、文書は自動で開かない。ファイル一覧かコマンドパレットから選んで開く。空の `content/` でも起動できる。画面の再読み込みやブラウザーの戻る・進むでは、その画面の履歴からタブを復元する。

### macOS で通常の Chrome と分ける

Viewer を Chrome のウェブアプリとして一度インストールすると、Dock と ⌘Tab に通常の Chrome とは別のアプリとして表示される。追加の npm パッケージやビルドは不要だが、サーバーの起動は引き続き必要となる。

1. `pnpm start`、開発時は `DEV_PORT=8080 pnpm dev` でサーバーを起動する。
2. ターミナルに表示された URL を、通常の Chrome のタブで開く。既定の通常起動は `http://127.0.0.1:3000`、上記の開発起動は `http://127.0.0.1:8080`。
3. Chrome のメニューで「キャスト、保存、共有」→「ページをアプリとしてインストール」を選び、「Markdown Viewer」をインストールする。ウィンドウで開く設定を有効にする。通常のタブで開いてしまう場合は `chrome://apps` で Viewer の設定をウィンドウ表示に変更する。登録後に専用アプリを使っても、コピー内だけを閲覧・保存する制限は変わらない。
4. 以後は同じ URL でサーバーを起動すると、インストール済みのアプリを自動で開く。開発中のソース変更ではウィンドウを追加せず、既存の画面を ⌘⇧R で再読み込みする。

URL はホスト名・ポートまで一致させる。`localhost` と `127.0.0.1`、異なるポートは別の登録になる。`PORT=0` や開発ポートの自動変更で URL が変わった場合は、その URL 用のアプリがないため Chrome アプリモードで開く。独立アプリを使い続ける場合は、登録時と同じ固定ポートを使う。アプリはオフライン閲覧用ではなく、Service Worker や文書のオフラインキャッシュは追加しない。

自動探索の対象は `~/Applications/Chrome Apps.localized/` と `/Applications/Chrome Apps.localized/`。アプリを移動した場合は、起動対象を明示できる。

```sh
VIEWER_APP_PATH="$HOME/Applications/Chrome Apps.localized/Markdown Viewer.app" pnpm start
```

`VIEWER_APP_PATH` は macOS 専用で、現在の URL 用の Viewer アプリだけを指定できる。パスや登録 URL が違う場合はエラーを表示し、別のアプリや Chrome を代わりに開かない。自動探索で見つからない場合や macOS の起動要求が失敗した場合は、Chrome アプリモードに戻る。`CHROME_PATH` だけを指定した場合は自動探索をせず、その Chrome をアプリモードで開く。両方を指定した場合は `VIEWER_APP_PATH` を優先する。`--no-open` はどちらの自動起動も止める。

旧 `md.localhost` 用の Viewer アプリを使っていた場合は、`127.0.0.1` の URL でインストールし直す。以前の Caddy とサーバーを停止し、`VIEWER_ORIGIN` を設定していた場合は解除してから起動する。

登録を削除するには Chrome の `chrome://apps` から Viewer をアンインストールする。再登録する場合は、同じ URL のサーバーを起動して上記の操作を行う。サーバーを再起動した後は、開いたままのアプリも ⌘⇧R で再読み込みする。

## コピーの管理

アプリは、このリポジトリの `content/` にある文書だけを開く。コピー元にはフォルダーを指定する。

```sh
# content/notes/ にコピー（既定のコピー名は元フォルダー名）
pnpm copy-docs "/Users/you/Documents/notes"

# コピー名を明示する。日本語・空白も使用可能
pnpm copy-docs "/Users/you/Documents/notes" "読書メモ"

# 別のフォルダーも追加できる
pnpm copy-docs "/Users/you/Documents/work" "work-notes"
```

- `.md` / `.markdown` と PNG / JPEG / GIF / WebP / AVIF だけを、フォルダー構造とファイルの内容を変えずにコピーする。
- Markdown は 1 ファイル 1 MiB、画像は 1 ファイル 5 MiB、フォルダーは深さ 32 までコピーできる。対応ファイルのサイズやフォルダーの深さが上限を超える場合、または Markdown がない場合はコピーを中止し、その実行で作ったコピーだけを削除する。元ファイルは変更しない。
- シンボリックリンクはファイル・フォルダーともスキップし、リンク先はコピーしない。通常ファイル以外と、`.git` / `node_modules` / `.DS_Store` も除外する。
- コピー名には、UTF-8 で 255 バイト以内のフォルダー名を指定する。先頭の `.`、前後の空白、区切り文字、除外名（`node_modules` など）は使えない。
- **既存の同名コピーは上書きしない。** 元文書の更新を取り込むには、別のコピー名で実行する。コピーと元ファイルは同期せず、保存済みマーカーも新しいコピーへは引き継がない。
- マーカーはコピーだけに保存し、元ファイルには反映しない。必要なマーカーを退避せずにコピーを削除しない。
- 不要なコピーはサーバーを停止してから、`content/` 内の該当フォルダーを手動で削除する。`content/` 自体と `.gitkeep` は残す。
- コピー元の中に `content/` がある場合も、`content/` の中にコピー元がある場合もコピーできない。コピー先ルート自体をシンボリックリンクにすることもできない。コピーには `pnpm copy-docs` を使い、`content/` にシンボリックリンクやハードリンクを手動で追加しない。
- `content/` のコピーは Git の対象外だが、暗号化はしない。機密文書の複製・バックアップ・削除は利用者が管理する。
- ファイル件数やコピーの合計サイズには固定上限がない。大量のファイルはディスク容量・探索時間・メモリー使用量を増やすため、対象を絞ってコピーする。

コピー途中のファイルが一覧に表示されないよう、コピーはサーバーを停止してから行うことを勧める。起動中に追加した場合は、「コマンドパレット」で `content/` を開き直すか、サーバーを再起動して ⌘⇧R / Ctrl+Shift+R で画面全体を再読み込みする。

## 起動オプション

```sh
# パス引数・設定ファイルのパス指定なし: content/ 全体を再帰的に一覧登録
pnpm start

# 起動時の表示範囲をコピー内に絞る（複数指定可）
pnpm start content/notes/one.md content/work-notes/two.md
pnpm start content/notes

# パス引数のフォルダーを再帰的に探す
pnpm start --recursive content/notes

# 空きポートを自動で選ぶ（3000 番が使用中の場合にも使える）
PORT=0 pnpm start

# 閲覧ウィンドウを自動で開かず、URL だけ表示する
pnpm start --no-open

# ショートカットとコピー閲覧の案内を最初から表示しない
pnpm start --no-notices

# Chrome の実行ファイルを明示する
CHROME_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" pnpm start
```

`PORT` は 0〜65535 の整数で、既定値は 3000。`0` を指定すると空きポートを選ぶ。固定ポートが使用中の場合は起動に失敗し、自動で別ポートには切り替えない。

起動時にフォルダーのパスを指定した場合は、既定ではその直下だけを探す。サブフォルダー内も探すには `--recursive` を付ける。起動引数にも設定ファイルにもパスを指定しなければ、常に `content/` 全体を再帰的に探す。起動時の絞り込みはアクセス制限ではなく、コピー内の別のパスも画面から開ける。

### 毎回同じパスと設定で起動する

リポジトリ直下に、Git の対象外となる `dev.local.json` を作成する。`pnpm start` / `pnpm dev` の両方でこの設定を読み込む。これまで開発時だけに使っていた設定も、通常の閲覧に適用されるため、特に `allowHtml` の値を確認する。

```json
{
  "paths": ["content/notes-one", "content/notes-two"],
  "recursive": false,
  "allowHtml": false,
  "hideNotices": false
}
```

- `paths` は必須で、`content/` 内のフォルダーや Markdown ファイルのパスを文字列の配列で指定する。空配列なら `content/` 全体を再帰的に登録する。コピー元など外部のパスは使えず、起動時の絞り込みはアクセス制限にはならない。
- 起動引数でパスを指定すると、設定ファイルの `paths` を使わず、引数のパスを登録する。`--no-open` などのフラグだけなら、設定ファイルのパスを使う。
- `recursive: true` は `--recursive` と同じで、指定したフォルダーのサブフォルダー内も探す。
- `allowHtml: true` は `--allow-html` と同じで、そのサーバーで開くすべての Markdown の生 HTML を描画する。**通常起動にも適用されるため、開くファイルがすべて信頼できることを確認する。** スクリプト・フォーム・外部リソースの制限は維持するが、任意の HTML を安全に表示できることは保証しない。生 HTML の相対リンクはアプリ内タブで開かず、`<img>` の相対パス画像も読み込まない。
- `hideNotices: true` は `--no-notices` と同じで、ショートカットとコピー閲覧の案内だけを非表示にする。読み込み中・操作結果・エラーは引き続き通知する。
- `recursive` / `allowHtml` / `hideNotices` は省略すると `false`。いずれもパス引数の有無にかかわらず適用する。起動引数のフラグで有効にできるが、設定ファイルの `true` を打ち消す起動フラグはない。

設定ファイルがなければ起動引数と既定値を使う。JSON や項目の形式が不正な場合は、パス引数を指定しても閲覧サーバーは起動しない。設定を変更したらサーバーを再起動し、既存の画面も ⌘⇧R / Ctrl+Shift+R で再読み込みする。

## ファイルを開く

- ファイルツリーから選ぶか、画面上部の「コマンドパレット」（⌘⇧P / Ctrl+Shift+P）で `content/` 内のファイルやフォルダーのパスを入力する。相対パスはサーバーを起動したディレクトリを基準に指定する。絶対パスや `~/...` も、コピー内を指す場合に限り使える。
- ツリーは `content/` 自体を表示せず、直下のフォルダーと Markdown から並べる。登録済みの Markdown がないフォルダーは表示しない。起動パスを絞った場合や後から文書を開いた場合も、`content/` からの階層を保つ。表示上の階層だけを整え、登録対象や相対リンク・画像の許可範囲は変えない。
- コマンドパレットでフォルダーを開くと、その中の Markdown をツリーに登録し、最初の 1 件だけをタブで開く。他のファイルはツリーから選ぶ。ツリーのフォルダーは初期状態では閉じている。検索中は一致するファイルの親を展開し、検索を消すと元の展開状態に戻る。
- 画面の「サブフォルダーも含める」は初期状態で有効。画面からフォルダーを開くときに適用し、起動引数には影響しない。
- **コピー元など `content/` 外のパスは、起動引数・画面入力・履歴復元のいずれでも拒否する。** 外部へのシンボリックリンクも開けない。
- ブラウザーのファイル・フォルダー選択とドラッグ＆ドロップによる取り込みには対応しない。ドラッグ操作は、開いているアプリ内タブの並び替えだけに使える。

### 開き方による違い

どの開き方でもコピーだけが対象で、マーカーはコピーに保存する。

| 開き方 | Markdown 記法の相対リンク・画像の許可範囲 |
| --- | --- |
| 起動引数・設定ファイルともパス未指定で起動 | `content/` 全体 |
| フォルダーのパスで開く | 指定したフォルダー以下 |
| 単独ファイルのパスで開く | ファイルの親フォルダー以下 |

設定ファイルで指定したパスも同じ範囲となる。いずれも `content/` の外には出られない。選択フォルダーの外でもコピー内であれば、パスを明示して開き直せる。

## 読む・操作する

⌘ は Command、⇧ は Shift キーを表す。⌘ / Ctrl と併記した操作では、macOS は ⌘、Windows / Linux は Ctrl を使う。

| 操作 | 動作 |
| --- | --- |
| 「コマンドパレット」、⌘⇧P / Ctrl+Shift+P、⌘P / Ctrl+P | コピー内のパスを開く、または登録済みのファイル名を検索。↑↓ と Enter でも選べる |
| 「全画面表示」、⌘⇧F / Ctrl+Shift+F | Viewer のツリー・タブなどを隠して本文を表示。Chrome 自体の全画面化ではない。同じ操作、または Esc で戻る |
| / | ツリーの検索欄にフォーカスする。全画面表示中は通常表示に戻る。入力欄・編集中の要素・日本語変換中には反応しない |
| Ctrl+@（US 配列では Ctrl+Shift+2） | ツリーの検索欄と表示中の本文のフォーカスを切り替える。タブがない場合は検索欄に留まる。検索欄へ移る際は全画面表示を解除する |
| Ctrl+Tab / Ctrl+Shift+Tab | 見た目の並び順で次 / 前のタブへ移動する。末尾と先頭を循環し、複数選択は解除する。移動後は本文にフォーカスする |
| サイドバーのアイコン、⌘B / Ctrl+B | ツリー・目次の表示を切り替える。隠しても幅を保つ。/ や Ctrl+@ で検索欄へ移る場合は再表示する |
| 復元アイコン、⌘⇧T / Ctrl+Shift+T | 最後に閉じたアプリ内タブを復元する。一括で閉じた場合はその操作分をまとめて復元する |
| ⌘F / Ctrl+F | 表示中の本文内を検索する。ツリーのファイル名検索とは別の機能 |
| ⌘G / Ctrl+G、⌘⇧G / Ctrl+Shift+G | 次 / 前の一致箇所へ移動する。本文検索欄の Enter / Shift+Enter も使える |
| ⌘W / Ctrl+W | 選択したアプリ内タブをまとめて閉じる。最後のタブを閉じても Viewer のウィンドウは残す |
| ファイルツリー上で ⌘← | 展開されているフォルダーをすべて閉じる |
| タブの ← → / Home / End | 表示するタブを切り替える。Shift と組み合わせると範囲選択。Delete / Backspace で選択したタブを閉じる |
| 「すべて閉じる」 | すべてのアプリ内タブを閉じる。ツリーの一覧は残る。タブがないときだけ無効 |
| ツリー検索欄の「まとめて開く」 | 検索結果をすべてアプリ内タブで開く。空の検索や一致なしの場合は無効 |
| ブラウザーの戻る・進む | 表示するタブ、開閉、並び順を履歴から復元する |
| 目次・見出しリンク | 本文の見出しへ移動する |
| Markdown 内の相対リンク | 許可範囲内の Markdown をアプリ内タブで開く |
| 本文上部の「再読み込み」、⌘R / Ctrl+R | 表示中の文書だけをコピーから読み直す。コピー元からの再コピーでも、Viewer 全体の再読み込みでもない |
| Raw / Preview、⌘⇧V / Ctrl+Shift+V | Markdown 原文とプレビューを切り替える。ボタンは切り替え先を示す |
| 月 / 太陽のアイコン | ダークモード / ライトモードに切り替える。初回は OS の設定に従い、以後は選択したテーマを使う。アイコンは切り替え先を示す |
| サイドバーの境界をドラッグ | ファイルツリーと本文の幅を調整する |

ブラウザー標準のショートカットの一部は、Viewer 内の操作に割り当てている。案内またはコマンドパレット内の「ショートカットの詳細」を選ぶと、別のブラウザータブで使い方を確認できる。

⌘W / Ctrl+W は Chrome アプリモードでの利用を想定する。通常の Chrome タブではブラウザーがキー操作を優先し、Viewer ごと閉じる場合がある。Viewer 内のタブだけを閉じるには、× ボタン、右クリックメニュー、またはタブにフォーカスして Delete / Backspace を使う。Viewer 外にフォーカスがある場合は Chrome の操作になる。

ダイアログ表示中は、Viewer が受け取った閉じる・復元・再読み込み・タブ移動・サイドバー・本文検索・表示切り替えのショートカットを実行しない。日本語変換中もショートカットで操作を中断せず、入力欄や編集中の要素では ⌘B / Ctrl+B と ⌘⇧V / Ctrl+Shift+V の標準動作を保つ。⌘P / Ctrl+P は印刷ではなくコマンドパレットを開く操作に、⌘⇧T / Ctrl+Shift+T は Chrome ではなく Viewer 内のタブを復元する操作に使う。

### 案内と通知を閉じる

画面上部のショートカットの案内と「コピーを閲覧中」の通知は、それぞれの × ボタンで閉じられる。閉じた案内の分だけ本文の表示領域が広がり、タブの切り替えや本文の再読み込みでは再表示しない。画面全体を再読み込みすると、再び表示する。

最初から表示しない場合は `pnpm start --no-notices` または `pnpm dev --no-notices` で起動する。対象はこの 2 つの案内だけで、読み込み中・操作結果・エラーは引き続き通知する。本文の読み込み状況は本文領域内に表示する。それ以外の通知は × で閉じられ、後の操作で新しい通知があれば表示する。案内を非表示にしても、「コマンドパレット」内からショートカットの詳細を開ける。

### 配色と入力欄

ダークモードは Gruvbox Dark Hard を基にした配色で、ライトモードは同系統の明るい配色を使う。UI と Preview 本文には BIZ UDPゴシック、Raw とコードには等幅の BIZ UDゴシックを使い、日本語と英数字を同じ書体で表示する。それぞれ通常・太字を同梱し、収録外の文字や絵文字は OS のフォントで補う。フォントとアイコンはローカルから読み込み、CDN は使わない。同梱フォントはブラウザーにキャッシュし、フォントの更新時には自動で新しいものを読み込む。

本文外のボタンとテキスト入力欄は高さを 28px にそろえ、ボタンの文字を上下中央に配置する。通常のボタンは枠線を表示せず、操作できるときは通常の文字色、無効なときは薄く表示する。ホバー時は背景色を変え、キーボード操作時はフォーカス枠を表示する。マーカーの色ボタンには、色を見分けるための枠を残す。狭いサイドバーでは、検索欄の「まとめて開く」ボタンが次の行に移る。狭い画面では、ツリーと目次の表示領域の高さを固定し、項目が多い場合はその領域内をスクロールする。

### 本文内を検索する

⌘F / Ctrl+F で本文の検索欄を開く。表示中の Preview のテキスト、または Raw の原文を、大文字・小文字を区別せず文字列として検索する。正規表現ではなく、`[` や `+` もそのままの文字として扱う。非表示の要素や画像のエラー注記は Preview の検索対象に含めない。

一致件数と、現在表示している一致箇所の番号を表示する。↑↓ ボタン、Enter / Shift+Enter、⌘G / ⌘⇧G（Ctrl+G / Ctrl+Shift+G）で次・前の一致箇所へ移動し、末尾と先頭を循環する。現在の一致箇所だけを強調する。タブや Raw / Preview を切り替えても検索語を保つ。Esc または × で閉じ、次の検索にも同じ語を使える。検索はファイルを書き換えず、マーカーとしても保存しない。

Esc はメニューやダイアログを閉じる操作にも使える。本文ではマーカー選択、本文検索、全画面表示の順に解除する。

### 検索結果をまとめて開く

ツリーの検索は、登録済みのファイル名とパスが対象で、本文の全文検索ではない。入力が止まってから約 150ms 後に結果を更新し、日本語変換中は更新しない。結果の更新を待つ間は「まとめて開く」を無効にする。前後の空白を除いた検索文字列があり、一致するファイルが 1 件以上なら「まとめて開く」を使える。一致件数は検索欄の下に表示する。折りたたまれたフォルダー内も含め、検索結果全件が対象となる。

開いているタブは重複追加せず、新しいタブをツリーの並び順で末尾に追加する。表示中の本文とスクロール位置は変えず、タブがない場合だけ最初の結果を表示する。新しく追加したタブを自動で複数選択することはない。追加操作は履歴の 1 回分となり、戻る操作で取り消せる。

本文は実際に表示したときだけ読み込む。新しく追加するタブが 50 件以上なら確認画面を表示する。件数制限はないが、多数のタブは画面の描画時間とメモリー使用量を増やすため、必要に応じて検索を絞る。

### タブをまとめて操作する

タブを切り替えても読んでいた位置を保持し、Raw と Preview の位置は別々に記憶する。ただし、閉じたタブの復元、ブラウザー履歴からの復元、画面全体の再読み込みでは位置を引き継がない。本文はフォントの読み込みと表示位置の復元が済んでから表示する。初回など読み込みに時間がかかる場合は、本文領域内に「読み込み中…」と表示する。この表示のために、画面上部の通知領域の高さが変わることはない。

Shift+クリックで、最初に選んだタブからクリック先までを範囲選択する。通常クリックで単一選択に戻る。背景色が一括操作の対象、アクセント線が表示中のタブを示す。閉じる操作でファイルは削除しない。

タブをドラッグして並び替えられる。右クリック、またはタブ上の Shift+F10 で、パスのコピー・再読み込み・左右への移動・閉じる操作を選べる。メニューは ↑↓ と Enter でも操作できる。パスのコピーにはブラウザーのクリップボード権限が必要な場合があり、失敗時は画面に通知する。相対パスは `content/` を除いたコピー内のパスとなる。

右クリックしたタブが選択範囲内なら選択を保ち、範囲外ならそのタブだけを選択する。「選択したタブを閉じる」以外は、右クリックしたタブを基準に操作する。再読み込みを選ぶと、そのタブを表示して本文を読み直す。

閉じたタブの記録は、この画面で行った直近 20 回分の閉じる操作まで保持する。復元すると元の位置にタブを戻し、本文はコピーから読み直す。コピー内のパスと参照元フォルダーを再検証するため、削除されたファイルやコピー外へ向くリンクは復元しない。復元できないファイルがあれば通知し、残りだけを開く。画面全体を再読み込みすると閉じたタブの記録は消える。

### マーカーを保存する

プレビューで文章を選択し、近くに表示されるポップアップから緑・黄色・オレンジ・ピンク・青を選ぶ。表の見出し・セル内の文章も選択できるが、ファイルパスなど本文外を選択した場合はポップアップを表示しない。コピーした Markdown に `<mark data-mdv-color="yellow">...</mark>` のようなタグを保存する。この形式のマーカーは、生 HTML を許可していない場合も描画する。

既存のマーカーを選択するかクリックすると、現在の色に黒丸を表示する。別の色を選ぶと色を変更でき、× ボタンでマーカーを外せる。**マーカーの一部だけを選択した場合も、色変更・削除はそのマーカー全体に適用する。** 再描画後も全画面表示と読んでいた位置を維持する。

以下の選択には対応しない。ポップアップが表示されない場合は、コードなどを含まない文章だけに選択範囲を狭める。

- コードブロック・インラインコードを含む範囲。
- 文字参照（`&amp;` など）やエスケープを含み、表示文字列と原文を対応付けられない範囲。
- 複数の既存マーカーをまたぐ範囲、またはマーカーの内側と外側にまたがる範囲。

保存時にコピーが別のアプリなどで更新されていた場合は、上書きせずエラーにする。「再読み込み」を押して選択し直す。Markdown の構造を保てない場合も保存を中止するため、選択範囲を狭める。マーカー追加後も 1 ファイル 1 MiB の上限が適用される。

### ブラウザーの再読み込みと保存される設定

- Viewer 全体を読み込み直すには ⌘⇧R / Ctrl+Shift+R を使う。サーバー再起動後もこの操作が必要となる。
- 開いていたタブのパス・参照元フォルダー・並び順・表示中のタブをセッション履歴に保存する。再読み込み時は、コピー内かを再検証して本文を読み直す。複数選択は保存しない。履歴を消去した場合は復元できない。
- 画面から登録したフォルダーは、ブラウザーの再読み込み時に再探索しない。タブを開いていなかったファイルを再表示するには、フォルダーを開き直す。
- 起動時に登録した一覧は、ブラウザーの再読み込み後もツリーに追加する。履歴に開いていたタブがない場合は、トップページを表示する。
- テーマとサイドバー幅を localStorage に保存する。テーマは同じオリジンの別タブにも反映する。保存が禁止されていても、そのページ内で切り替えられる。

## 対応範囲と制限

- 見出し、リスト、表、取り消し線、引用、コード、リンクに対応する。GFM 完全互換ではなく、タスクリスト・脚注の専用拡張はない。
- Mermaid は図ではなくコードとして表示し、数式の描画やコードの構文色分けには対応しない。
- Markdown は 1 ファイル 1 MiB までで、コピー時・閲覧時・保存時にこの上限を適用する。
- 対応画像は PNG / JPEG / GIF / WebP / AVIF、1 ファイル 5 MiB まで。コピー時と閲覧時に適用する。Markdown 記法の画像は相対パスだけを読み、1 ページ 100 件まで。外部 URL・絶対パスの画像は読み込まず、HTML・SVG は画像として配信しない。
- コピーと再帰探索は深さ 32 まで。`.git` / `node_modules` / `.DS_Store` とシンボリックリンクをスキップする。
- ファイル件数、登録総数、探索項目数、コピーの合計サイズには固定上限がない。本文は選択時に読み込む。大量のファイルはディスク容量・探索時間・メモリー使用量を増やすため、対象を絞ってコピーする。

## 生 HTML を表示する場合

既定では生 HTML を文字として表示し、`<!-- ... -->` のコメントだけを非表示にする。コード内のコメント表記はそのまま表示する。アプリが保存する固定形式のマーカー用タグは、生 HTML を許可しなくても描画する。

信頼できるファイルで `<details>` / `<summary>` などを描画する場合は、次のように起動する。

```sh
pnpm start --allow-html content/notes/trusted.md
```

`--allow-html` と設定ファイルの `allowHtml: true` は、そのサーバーで開くすべての Markdown に適用する。コピー内でも信頼できるファイルだけを開く。スクリプト・フォーム・外部リソースの制限は維持するが、任意の HTML を安全に表示できることは保証しない。

文書間の移動や画像表示には Markdown 記法を使う。生 HTML の相対リンクはアプリ内タブで開かず、`<img>` の相対パス画像も読み込まない。
